Prompt design · refined v3 · one-shot
The actual prompt used in the final evaluation
Six sectional blocks · sequential structure · one annotated example
1
Task definition
TASK: Tag a single room-camera frame (IR/visible) with predefined tags. Return STRICT JSON ONLY (no markdown, no extra text). **Must be valid JSON**.
2
Decision rules · WHAT TO DO
1) First decide if the patient is visible. - If patient is visible: include 'patient' in situation_tags. - If patient is NOT visible: do NOT guess pose/location; set poses=["other"] and locations=["other"]. 2) If patient is visible, choose EXACTLY ONE best pose in poses (or "other" if unclear). 3) If patient is visible, choose EXACTLY ONE best location in locations (or "other" if unclear). 4) Add other situation_tags if they are visible (staff types, interactions, rails, blanket, cleaning, etc.). 5) Add sequence_events only when applicable (e.g., subject_identified if patient clearly identifiable). 6) Tell how many people you see (patient + staff) in "people_count" field. 7) Assign 'operator_patient_interaction' only if an operator/staff member is visibly touching the patient. IMPORTANT RULES: - Do not invent tags just to avoid empty outputs. - If a visible person is clearly the patient, include 'patient' in situation_tags. - Do not guess staff, interaction, or anomaly tags when uncertain.
3
Tag vocabulary · ALLOWED TAGS
- situation_tags: [educator, doctor, nurse, oss, cleaner, visitor, patient, room_cleaning, patient_cleaning, patient_change, patient_eating, patient_sleeping, patient_reading, patient_watching_tv, operator_patient_interaction, visitor_patient_interaction, wheelchair, blanket, patient_lift, waiting_bed, bedrail_sx, bedrail_dx, bedrail_cover_sx, bedrail_cover_dx] - sequence_events: [risk_of_falling, operator_patient_interaction, person_down, bed_rails_down, subject_identified, subject_lost, body_part_out_of_bed_perimeter] - poses: [lying_prone, lying_supine, lying_curled_up_left, lying_curled_down_left, lying_curled_up_right, lying_curled_down_right, seating_edge, seating_over, standing, kneeling, other] - locations: [other, on_bed, on_floor, on_chair]
4
Tag definitions · semantic grounding
key refinement
- situation_tags: - oss: An OSS or auxiliary healthcare staff member is present in the scene. - patient: The patient is visible in the scene. - wheelchair: A wheelchair is visible in the scene. - bedrail_sx: The left-side bed rail is visible. - bedrail_cover_sx: The left-side bed rail cover is present. - operator_patient_interaction: When a healthcare operator is directly interacting with the patient. ... (every tag carries a one-line definition) - sequence_events: - risk_of_falling: Only from bed. Use only if clear fall-risk cues are visible. - person_down: A person is on the floor (fallen/lying/sitting on floor). - subject_identified: Patient clearly visible and identifiable. - body_part_out_of_bed_perimeter: Any joint outside bed perimeter. - poses: - lying_supine: The patient is lying face up. - seating_edge: The patient is seated on the edge of the bed or chair. - other: None of the above poses, or pose cannot be determined. - locations: - on_bed: The subject is on the bed (not just touching it, but on it). - on_floor: The subject is on the floor.
5
Output schema
OUTPUT JSON SCHEMA (single line; stop after '}'): { "tags": { "situation_tags": ["..."], "sequence_events": ["..."], "poses": ["..."], "locations": ["..."] }, "description": "4-5 short sentences about the scene", "people_count": "Tell how many people you see (just a number)" }
6
One-shot example · image + annotation
