Final prompt structure

Six sequential blocks · refined wording · semantic grounding · one-shot example

Stage 1 + 2 winning configuration

1 Task definition === task ===
TASK: Tag a single room-camera frame (IR/visible) with predefined tags. Return STRICT JSON ONLY (no markdown, no extra text). **Must be valid JSON**.
2 Decision rules === what to do ===
1) First decide if the patient is visible. - If patient is visible: include 'patient' in situation_tags. - If patient is NOT visible: do NOT guess pose/location; set poses=["other"] and locations=["other"]. 2) If patient is visible, choose EXACTLY ONE best pose. 3) If patient is visible, choose EXACTLY ONE best location. 4) Add other situation_tags if they are visible. 5) Add sequence_events only when applicable. 6) Tell how many people you see in "people_count". 7) Assign 'operator_patient_interaction' only if visibly touching. IMPORTANT RULES: - Do not invent tags just to avoid empty outputs. - Do not guess staff, interaction, or anomaly tags when uncertain.
3 Tag vocabulary === allowed tags ===
situation_tags: [ educator, doctor, nurse, oss, cleaner, visitor, patient, room_cleaning, patient_cleaning, patient_change, patient_eating, patient_sleeping, patient_reading, patient_watching_tv, operator_patient_interaction, visitor_patient_interaction, wheelchair, blanket, patient_lift, waiting_bed, bedrail_sx, bedrail_dx, bedrail_cover_sx, bedrail_cover_dx ] sequence_events: [ risk_of_falling, operator_patient_interaction, person_down, bed_rails_down, subject_identified, subject_lost, body_part_out_of_bed_perimeter ] poses: [ lying_prone, lying_supine, lying_curled_up_left, lying_curled_down_left, lying_curled_up_right, lying_curled_down_right, seating_edge, seating_over, standing, kneeling, other ] locations: [other, on_bed, on_floor, on_chair]
4 Tag definitions key refinement === definitions ===
situation_tags: oss: An OSS or auxiliary healthcare staff member is present. patient: The patient is visible in the scene. wheelchair: A wheelchair is visible in the scene. bedrail_sx: The left-side bed rail is visible. bedrail_cover_sx: The left-side bed rail cover is present. operator_patient_interaction: Healthcare operator directly interacting with the patient. ... every tag carries a one-line definition sequence_events: risk_of_falling: Only from bed. Use only if clear cues visible. person_down: A person is on the floor. subject_identified: Patient clearly visible and identifiable. poses: lying_supine: Patient lying face up. seating_edge: Patient seated on the edge of bed or chair. other: None of the above, or pose cannot be determined. locations: on_bed: Subject is on the bed (not just touching it). on_floor: Subject is on the floor.
5 Output schema === output format ===
// Single line, stop after final '}' { "tags": { "situation_tags": ["..."], "sequence_events": ["..."], "poses": ["..."], "locations": ["..."] }, "description": "4-5 short sentences about the scene", "people_count": "number" }
6 One-shot example stage 2 addition image + annotation

Two OSS staff members are helping the patient. The right bed rail is raised and covered, while the left bed rail is lowered. There is the risk of falling for the patient.", "people_count": "3" }
Why this structure works. Each section is separated by an explicit header, reducing cross-section interference in the model's attention. Section 4 grounds each label in project-specific meaning. Section 6 anchors the expected output format with a concrete annotated pattern.
